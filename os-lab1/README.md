## Условие

Родитель читает первой строкой имя выходного файла, создаёт дочерний процесс
и передаёт ему имя файла аргументом при запуске отдельной программы.
Последующие строки содержат произвольное количество чисел типа `int`.
Родитель передаёт их по `pipe1` в стандартный ввод ребёнка. Ребёнок делит
первое число последовательно на остальные и записывает результат каждой
строки в созданный им файл. Проверку деления на ноль выполняет ребёнок;
при обнаружении нулевого делителя оба процесса завершаются.
Обратный канал `pipe2` сообщает родителю об ошибке.

## Сборка и запуск в Linux

Нужны GCC или Clang и make. Из каталога `os-lab1`:

```sh
make
./parent
```

Пример ввода:

```text
result.txt
100 2 5
-20 3
7
```

После ввода нажмите `Ctrl+D` на пустой строке для EOF. Файл `result.txt`:

```text
10
-6
7
```

Для запуска из другого каталога задайте путь к ребёнку:

```sh
/path/to/os-lab1/parent /path/to/os-lab1/child
```

Путь к выходному файлу задаётся относительно текущего рабочего каталога.
Существующий выходной файл **перезаписывается**. Без второго аргумента родитель
запускает `./child` из текущего каталога. При интерактивном запуске программа
не печатает приглашений: сразу вводите имя файла.

Воспроизводимый запуск из оболочки:

```sh
printf 'result.txt\n100 2 5\n-20 3\n7\n' | ./parent
cat result.txt
```

Здесь `printf` — команда оболочки для подачи тестовых данных; в программе
`stdio.h`, `printf`, `scanf`, `malloc` и функции преобразования строк не используются.

## Обработка данных и ошибок

- Деление целочисленное, слева направо, с усечением к нулю: `-20 / 3 = -6`.
- Строка из одного числа записывает это число. Ноль в первом числе допустим.
- Допустимы знаки `+`/`-`, пробелы, табуляция, CRLF; последняя строка может
  завершаться EOF без `\n`.
- Числа должны помещаться в `int` (на проверенной платформе — от −2147483648
  до 2147483647). Нулевой делитель, `INT_MIN / -1`, неверный токен или пустая
  строка завершают работу с кодом 1. Код успеха — 0.
- Ошибочная строка не записывается; результаты предыдущих строк сохраняются.
  Строки после ошибки не обрабатываются.
- EOF сразу после имени файла создаёт пустой файл и нормально завершает работу.
- Обработка чисел потоковая: число токенов и длина команды не ограничены
  буфером 4096 байт. Имя файла ограничено 4095 байтами, включая возможный `\r`.
- Проверяются ошибки системных вызовов, короткие записи и `EINTR`.
  Системные ошибки выводятся в stderr с числовым `errno`.

## Организация процессов

```text
stdin пользователя -> parent -> pipe1 -> stdin child
                                       child -> выходной файл
                     parent <- pipe2 <- stdout child
                     stderr <- сообщения об ошибках обоих процессов
```

Ребёнок получает перенаправленные дескрипторы через `dup2`, затем запускается
через `execv`. В `pipe2` передаётся один байт `E` при ошибке; успешное завершение
обозначается закрытием канала. Родитель с помощью `poll` одновременно следит
за stdin и `pipe2`, поэтому ошибка ребёнка завершает родителя без дополнительного
ввода. При EOF родитель закрывает пишущий конец `pipe1`. Неиспользуемые концы
каналов закрываются, а `waitpid` забирает статус ребёнка. `SIGPIPE` игнорируется,
чтобы разрыв канала обрабатывался как ошибка `write`.

## Проверка

```sh
make test
```

Для тестов нужен Python 3. Тесты запускают настоящие процессы и проверяют
содержимое файла, коды завершения и диагностику. Включены 20 сценариев:
обычные вычисления, знаки и границы `int`, пробельные символы, EOF, имена с
пробелами, деление на ноль, переполнение, некорректный ввод, ошибки открытия
и `exec`, строка из 150001 числа, 1000 случайных команд и открытый stdin при ошибке.

Фактическая проверка 24.09.2026: **20/20**, GCC 15.3.0, POSIX-среда MSYS2
на Windows. Сборка выполнена с `-Wall -Wextra -Wpedantic -Wconversion -Wshadow
-Werror`. Непосредственный запуск под ядром Linux в текущей среде не выполнялся.
MSYS2 проверяет поведение через свой слой совместимости; перед сдачей на Linux
можно повторить `make test`.

В MSYS2 нужен именно компилятор `/usr/bin/gcc`, а не MinGW/UCRT GCC:

```sh
/usr/bin/gcc -std=c11 -O2 -Wall -Wextra -Wpedantic -Werror parent.c -o parent
/usr/bin/gcc -std=c11 -O2 -Wall -Wextra -Wpedantic -Werror child.c -o child
./parent
```

Поставляемые `parent.exe` и `child.exe`, если присутствуют, относятся к MSYS2;
для Linux пересоберите исходники. Они зависят от установленной MSYS2.
