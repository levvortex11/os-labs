## Сборка и запуск

В Linux или Ubuntu через WSL:

```sh
make
./merge 4
./merge 4 1000000
./merge 4 10 reverse
```

Формат: `./merge THREADS [SIZE] [random|sorted|reverse]`. Первый аргумент — общий предел потоков (от 1 до 256), второй — положительный размер массива (по умолчанию 5 000 000), третий — порядок данных (по умолчанию `random`). Это аргументы запуска, вводить элементы вручную не требуется. При неправильных аргументах программа завершается с сообщением об ошибке.

Генератор использует `srand(42)` для воспроизводимости в одной среде. Программа создаёт два одинаковых массива, сортирует один последовательно, другой параллельно, выводит оба времени, ускорение и эффективность. При размере до 20 также печатает массив до и после. Результаты двух сортировок и порядок элементов проверяются; успешный результат — `Check: OK`. Большие массивы не печатаются. Нужно около `3 * SIZE * sizeof(int)` байт для массивов, не считая стеков потоков.

## Алгоритм

`merge_sort` рекурсивно сортирует две половины и объединяет их через `merge`. В `parallel_sort` левая половина передаётся новому потоку, правая обрабатывается текущим. Слияние начинается после `pthread_join`.

Счётчик свободных мест изначально равен `THREADS - 1` и защищён мьютексом. Место резервируется перед созданием потока и освобождается после его завершения и `join`. Главный и ожидающие потоки входят в общий предел. Если свободных мест нет или участок короче 16384 элементов, используется последовательный алгоритм. Массив и буфер разделены между потоками на непересекающиеся участки.

## Проверка и демонстрация потоков

```sh
make test
python3 tools/check_threads.py
```

Выполнены 45 сравнений функций сортировки с независимой `qsort` и 22 проверки интерфейса запуска. Скрипт проверки потоков наблюдает `/proc/PID/status` и выводит снимок `ps -T`; при проверке пределы 1, 2, 3, 4, 8 соблюдались. Для небольшого массива реально используется только один поток.

Для ручной демонстрации на большом массиве:

```sh
./merge 4 10000000 &
pid=$!
ps -T -p "$pid"
wait "$pid"
```

В начале программа сортирует последовательно, поэтому первый снимок может содержать один поток. Повтори `ps -T -p "$pid"` во время параллельной части или используй скрипт.

## Измерения и отчёт

```sh
python3 tools/bench.py
```

Скрипт перезаписывает `report/measurements.csv`: три запуска для каждого размера, порядка данных и числа потоков. Сохраняются отдельные измерения и медианы. Ускорение в CSV равно отношению медиан последовательного и параллельного времени; эффективность — ускорение, делённое на заданный предел потоков. Время включает саму сортировку, создание и ожидание потоков, но не выделение памяти, генерацию и проверку результата. Последовательный запуск всегда идёт первым; на малых массивах важны шум измерений и прогрев.

Отчёт: `report/214_Вихарев_Лаб2.docx` и PDF. В Windows отчёт можно обновить командой `python tools/make_report.py` (python-docx, reportlab, шаблон из первой лабораторной). Команды и объяснения в старой версии с `--threads`, ручным вводом и проходами снизу вверх заменены новым интерфейсом.

Пример, по которому выбран интерфейс и рекурсивная структура: https://github.com/UIgylka/OS_labs_3sem/blob/main/main2.c. Ограничение потоков здесь реализовано общим счётчиком слотов.
